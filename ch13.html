    Chapter 13

    Weekly Reporting

    13.1 Weekly Task Report

    Recipient: Fire Chief Kenneth Hedges

    Due: Sunday evening (auto-generated via Power Automate)

    Format: Microsoft Word (.docx) with DFD branding

    Data Sources: SharePoint lists (Activities, Expenses, Events), Outlook Calendar

    13.2 Report Structure

    The weekly report follows a consistent structure that captures daily activities, events, budget expenses, and upcoming priorities:

    Daily Activity Log

    The main body of the report is a day-by-day table of activities:

    DayHoursActivities
    Monday0730-2000Monday Staff meeting. Event coordination for the week. [Description of key tasks and activities].
    Tuesday0800-2000[Description of activities]. Candidate emails. [Additional tasks].
    WednesdayOOS / hoursN/A (or description of activities if working)
    Thursday0730-2030[Description of activities]. CRR meeting. Candidate emails.
    Friday0730-2000Candidate emails. Weekly report. [Additional tasks].
    SaturdayOOS / hoursN/A (or description if working, e.g., Civil Service Exam day)

    Events Section

    List notable events attended or executed during the week (e.g., "Calhoun Middle School Recruiting", "Civil Service Exam").

    Budget Expenses Section

    List all P-Card expenditures for the week in the standard table format (Budget total, Amount, Account code, Description).

    Next Week Preview

    Brief day-by-day outline of planned activities for the following week. Example format:

    • M: Holiday / Staff meeting / [planned activity]
    • T: [planned activity]
    • W: [planned activity] / OOS
    • Th: CRR Meeting / [planned activity]
    • F: [planned activity]
    • S: OOS

    13.3 Report Formatting

    Weekly reports follow DFD branding standards:

    • DFD logo in header
    • Times New Roman 12pt font for body text
    • Red accent line (#CC0000) under header
    • Clean, professional formatting

    See the Power Automate Setup Guide (listed in Chapter 17.4) for automation workflow details.

    13.4 Power Automate Integration

    Weekly reports can be auto-generated from SharePoint lists using Microsoft Power Automate. The system pulls from:

    • CRR Weekly Activities list: Email logs, tasks completed
    • CRR Expenses list: Expense records with budget codes
    • ESO Events Log list: Community events attended
    • Outlook Calendar: Meetings and appointments

    The report flow runs every Sunday at 8 PM CST, compiles the week's data, generates a formatted document, and sends a notification email. See the Power Automate Setup Guide for complete configuration details.

    13.5 CRR Dashboard Slides

    The CRR Officer produces presentation slides that display on the department's First Arriving Dashboards system. These Chromebox-powered screens are installed at all nine fire stations, the Administration lobby, Fire Prevention/Inspections at the DSC, and Command displays. CRR slides rotate alongside ICS alert data, Telestaff roster information, turnout time data, and department announcements, giving station crews and visitors visibility into upcoming and completed community events.

    First Arriving Dashboards System

    First Arriving provides the digital signage platform used department-wide. Key operational details:

    • Support: support@firstarriving.com (email creates a ticket)
    • Knowledge Base: support.firstarriving.com/support/solutions
    • Wi-Fi: All devices connect via City of Denton Public Internet
    • Dashboard portal: portal.firstarrivingdigital.com/dashboard (used to refresh devices; Bret Densmore is admin)
    • Portal2: portal2.firstarrivingdigital.com/login (view-only access to all displays; no paid subscription required)

    Data feeds into the system from multiple sources:

    FeedDelivery MethodManaged By
    Roster DataTelestaff via SFTP (daily)Jim Barnes
    Turnout DataESO Ad Hoc Reporting via email (daily) [currently disabled pending NERIS transition]Alison Andrews
    Unit StatusTelestaff via SFTP (daily)Bret Densmore
    ICS AlertsEmail to dedicated First Arriving addressDavid Morin
    AnnouncementsGoogle Sheets[designated staff]

    ICS alert displays are filtered by station. Each station dashboard receives alerts only for its assigned units. The Fire Prevention/DSC display receives all fire, bomb, and mass casualty call types. The Administration lobby display is unfiltered and receives all department alerts.     All dashboard slides, including CRR content, are managed through a shared Google Slides deck:

    To publish a CRR slide, the CRR Officer generates the slide using the build script (see Build Process below), exports it as a PNG or copies the layout into the shared Google Slides deck, and the First Arriving system picks up the update automatically on the next display cycle.

    Standard Slide Format

    The standard CRR dashboard slide uses a white background with DFD branding elements drawn from the Knox Box site design system (dentonfire.github.io/Knox-Box/). The color palette is:

    ColorHexUsage
    Navy#152a40Title text, header row, footer bar, date range badge background
    Red#bf2726Overdue status badges
    Yellow#f9c031Subtitle text, yellow divider line, date range badge text, Scheduled status badges
    Green#28a745Completed status badges
    White#FFFFFFSlide background
    Light Gray#E8EDF2Alternating row backgrounds

    Slide Layout (16:9, 10 x 5.625 inches)

    The slide is organized into four zones from top to bottom:

    Header Zone (top 1.2 inches). DFD patch logo at top left (0.65 x 0.87 inches). Title "Community Risk Reduction" in Arial Black 22pt, navy. Subtitle "Community Events" in Arial Bold 13pt, yellow. Date range badge at top right with navy rounded rectangle background and yellow text. Yellow horizontal divider line below the header, full width.

    Summary Zone (1.2 to 1.8 inches). Three status chips showing counts for Completed (green dot), Scheduled (yellow dot), and Overdue (red dot) if applicable. Source attribution "Source: ESO Community Events" in italic at far right.

    Table Zone (1.8 to 5.0 inches). Navy header row with column labels: DATE, ACTIVITY, LOCATION, UNIT, STATUS. Alternating row backgrounds (light gray and white on white slides, or navy tint variations on dark slides). Each row contains: date and time (bold date, muted time), activity name in bold, location with address in muted text, assigned unit, and a color-coded status badge (rounded pill shape).

    Footer Zone (bottom 0.475 inches). Navy bar with thin yellow accent line on top. Centered text: "Denton Fire Department | Support Services Division | Captain Hunter Lott, CRRO" in muted text.

    BadgeColorCriteria
    COMPLETEDGreenEvent has occurred and been documented in ESO
    SCHEDULEDYellowEvent is confirmed and appears on the ESO calendar but has not yet occurred
    OVERDUERedEvent date has passed without a completion record in ESO

    Reporting Cadence

    Dashboard slides cover two-week windows aligned with the ESO event calendar. The CRR Officer produces these slides on a biweekly basis or as needed for department update meetings. Each slide reflects only the events within that specific date range. Because these slides display on station dashboards, crews can see their assigned community events for the current period without checking ESO directly.

    Data Source

    All event data is pulled from the ESO Community Events system. Events are logged by station crews and the CRR Officer. The ESO record for each event includes the date, time, activity name, location, and assigned unit or individual. The CRR Officer reviews ESO records for accuracy before producing the dashboard slide.

    Build Process

    Dashboard slides are generated using PptxGenJS (Node.js) via a build script. The script reads event data, applies the standard layout and color palette, and outputs a .pptx file. The build script and a background texture asset (navy with isometric cube pattern, matching the Knox Box site) are maintained in the CRR Officer's working files.

    To generate a slide, update the events array in the build script with current ESO data, then run:

    node build_slide.js

    The output file is saved as CRR_Community_Events_[date-range].pptx. After generating, export the slide as a PNG or recreate the layout in the shared Google Slides deck for First Arriving to pick up.

    Background Variants

    Three background options are available for the dashboard slide:

    1. Dark navy with cube texture (full coverage) -- matches Knox Box site exactly. Best for projected display on station dashboards.
    2. Dark navy with fading cube texture -- cubes visible at top, fading to solid navy in bottom third. Keeps visual interest while providing clean space for the event table.
    3. White background (standard) -- white slide with navy text and accent elements. Selected as the default for department meetings and printed handouts. Also works well on station dashboards in well-lit dayrooms.

    The background texture image (cubes_on_navy_fade_1920x1080.png) is a 1920x1080 PNG with the isometric cube pattern composited onto the navy background with a top-to-bottom opacity fade. It can be applied as a slide background in PowerPoint or Google Slides.
